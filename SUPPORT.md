# Support

Where to get help with Orjanda — from usage questions to security reports.
For contribution guidance, see [CONTRIBUTING.md](CONTRIBUTING.md).

## Channels

| Need | Where | Availability |
|---|---|---|
| Usage questions, "how do I…" | [GitHub Discussions](https://github.com/orjanda-framework/orjanda/discussions) | Enabled |
| Bug reports | [GitHub Issues — bug report template](https://github.com/orjanda-framework/orjanda/issues/new?template=bug_report.yml) | Open |
| Feature requests | [GitHub Issues — feature request template](https://github.com/orjanda-framework/orjanda/issues/new?template=feature_request.yml) | Open |
| Security vulnerabilities | [GitHub Security Advisories](https://github.com/orjanda-framework/orjanda/security/advisories/new) — see [SECURITY.md](SECURITY.md) | Private, do not file a public issue |
| Contributing | [CONTRIBUTING.md](CONTRIBUTING.md) | Always |

## Guidelines

- **Search before you ask.** Check the
  [docs](docs/), [Discussions](https://github.com/orjanda-framework/orjanda/discussions),
  and [existing issues](https://github.com/orjanda-framework/orjanda/issues)
  first — your question may already be answered.
- **One question per thread.** It keeps conversations findable for others.
- **Include context.** For bugs: Orjanda version/commit SHA, Go version,
  database dialect, and reproduction steps (see the bug template).
- **No secrets.** Never post credentials, DSNs, JWT secrets, or API keys in
  issues or discussions. If your report involves them, use a private security
  advisory instead.
- **Check the scope first.** Requests for out-of-scope features (plugins, MCP,
  MySQL dialect, multi-tenancy activation, etc.) will be closed — see
  [PRD §5 Non-Goals](docs/ORJANDA-PRD.md#5-non-goals).

## What to expect

This project is maintained by a single maintainer, so responses may take a
few days. Bug reports without reproduction steps, and questions that are
answered in the docs, may be closed with a pointer rather than a full reply.
